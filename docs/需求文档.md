# 求职助手 Job-Copilot · 需求文档（PRD）

> 版本：v1.0 ｜ 日期：2026-07-10 ｜ 定位：单用户本地工具
> 一句话：把"投得多"变成"投得准 + 谈得好"，用数据帮你找方向、测竞争力、提高回复率。

---

## 0. 阅读指引

本文档是后续所有开发的基准。它记录了**我们对齐后的共识**，包括几个对最初想法的**重要修正**（见 §2 设计红线）。如果你想改动方向，改这份文档即可。

## 1. 项目背景与目标

### 1.1 你是谁 / 要解决什么
- 单个求职者（先只给自己用），会装环境、能跑脚本。
- 处境：**骑驴找马、居安思危**——不一定马上离职，但要持续掌握自己在市场上的竞争力，并寻找可能的跳槽/换行方向。
- 痛点：不知道自己值多少钱、该往哪走、该补什么技能；手动投递效率低、招呼语没针对性、回复率低、面试准备无从下手。

### 1.2 核心价值主张（护城河）
本工具的真正价值**不在"海投"，在三件事**：
1. **找方向**：用市场数据反推适合你的行业/岗位方向（你目前还没定位）。
2. **测竞争力**：用"分组对照投递 + 已读不回率"量化你在不同档位/行业的抢手程度，并输出该补的技能树。
3. **谈得好**：定制招呼语、简历调整建议、HR回复起草、面试方向指导，全部基于真实JD和市场信息。

### 1.3 北极星指标
- **主指标**：邀约率（收到面试邀约数 / 投递数）。
- **过程指标**：已读率、已读不回率、回复率（按行业/岗位/薪资档位分组）。
- 已读不回率不是"失败率"，而是**竞争力信号**——用来定位你在市场中的位置和技能缺口。

### 1.4 非目标（明确不做）
- ❌ 不做多用户 SaaS、不做云部署、不做账号体系（数据全在本地）。
- ❌ 不做大规模爬取、不破解平台反爬、不多账号刷量。
- ❌ 不做全自动无人值守投递（原因见 §2）。
- ❌ 不采集他人简历、HR个人隐私等个人信息。

## 2. 设计红线（对最初想法的修正，必读）

这几条是架构级约束，是我基于风险和实效对最初需求的反驳与修正，已与你对齐。

### 红线一：不追求"一天投1000份"，改为"分组对照精准投递"
- **硬约束**：Boss直聘单账号每天主动打招呼约几十到100出头，超限即限流/封功能；一天1000份在单账号上**物理不可行**，只能靠多账号+代理（高封号风险 + 法律风险，有判例）。
- **更重要**：无脑海投（同一简历+同一招呼语）测到的是噪音，**无法归因**，不能告诉你该学什么、能不能换行。
- **替代方案**：**分组对照实验**。按"本行平级 / 高一档 / 换行目标"等分组，每组用贴合JD的定制招呼语，比较各组的已读/回复/邀约率。**100~300份精准分组 > 1000份海投**，信息量大得多且不封号。
- **目标重述**：两周内跑完一轮 200~300 份分组对照投递，产出一份《竞争力 + 行业方向》报告。

### 红线二：采集走"个人规模 + 公开数据"，不走大规模爬取
- 目标平台职位：用**你自己的登录态 + 浏览器自动化（Playwright）**，模拟正常浏览节奏，每天几百~一两千条，够用。
- 行业面数据：优先用**八爪鱼 / 公开页 / 公开薪酬报告**采集岗位JD、薪资范围、任职要求这类**企业公开信息**。
- 合规：抓岗位JD/薪资等公开信息、不破解反爬、控制频率 → 风险较低；一旦多账号破解、抓个人信息、高频压垮服务器 → 触碰《数据安全法》《个人信息保护法》及刑法285条。**我们只走前者。**

### 红线三：投递/招呼/回复是"AI起草 + 你一键确认"的半自动
- 全自动会同时毁掉你的号（风控）和口碑（HR一眼看穿模板），**反而降低回复率**。
- 系统把 80% 的活干完（匹配打分、定制招呼语、简历建议、HR回复起草），你花几秒审核确认再发。
- 回复率的提升来自"每条都真贴合JD"，不来自"投得多"。

### 关于八爪鱼（Octoparse）能用在哪
| 用途 | 是否适合 | 说明 |
|---|---|---|
| 抓行业/岗位**公开列表**（JD、薪资、要求） | ✅ 适合 | 行业分析主力，降低技术门槛 |
| 抓 **Boss直聘** 职位详情 | ⚠️ 不可靠 | 登录墙+加密+反爬强，八爪鱼常抓不动/被封 |
| **投递 / 打招呼 / 回复HR** | ❌ 做不到 | 八爪鱼只"读"不"操作"，须用 Playwright 带登录态 |

## 3. 功能需求（模块化）

你最初的 9 条需求，重组为 10 个模块。每条标注了对应关系。

### M1. 数据采集（对应需求1）
- **M1.1 目标平台职位采集**：Playwright 带你登录态，按你设定的关键词/城市/薪资/经验筛选，采集职位列表与详情（岗位名、公司、薪资、JD、任职要求、发布时间、HR活跃度等）。默认平台：Boss直聘、智联、猎聘、前程无忧（按可行性排序，优先低反爬的）。
- **M1.2 行业面数据采集**：八爪鱼/公开源采集更大范围的岗位JD与薪资，用于市场分析。
- **M1.3 采集节流**：随机化间隔、模拟人工节奏、单日额度上限、断点续采，保护账号。
- 输出：`data/raw/` 下的原始 JSON/CSV。

### M2. 数据清洗与整合（对应需求2）
- 去重（同公司同岗位多次发布）、字段标准化（薪资统一成"月薪下限/上限/13薪折算"，经验/学历分级）、技能关键词抽取（从JD里抽出硬技能/软技能/工具栈）。
- 城市、行业、职能三级标签归一化。
- 输出：`data/clean/` 结构化表 + 可导出 Excel/飞书表格（你在表里筛选和打"感兴趣"标记）。

### M3. 行业 / 市场分析（对应需求3、需求5）
- **市场画像**：目标关键词下的岗位数量、薪资分布（P10/P50/P90 即上下限与中位）、经验/学历要求分布、热门技能词云、招聘活跃公司 Top N。
- **行业上下限（需求5）**：某行业/岗位的薪资天花板与地板、进入门槛、增长趋势（用职位数量变化近似）。
- **换行探索（需求3）**：因为你还没定位，工具会用你现有背景当种子，扫描"薪资更高/需求更多/与你技能重叠度高"的相邻行业，给出**候选方向排行**。

### M4. 竞争力与技能树诊断（对应需求4、需求8）
- **技能差距**：把你的简历技能 vs 目标岗位JD要求的技能做交集/差集，输出"你已具备 / 你缺失 / 高频要求"三张清单。
- **技能树**：按目标方向生成"该学什么、优先级、学到什么程度"的路线图。
- **市场定位（需求8）**：结合薪资分布，估算你当前处于市场的哪个分位；结合下面的对照投递数据，验证并校准这个估算。

### M5. 竞争力实证 —— 分组对照投递与已读不回统计（对应需求6的量化部分）
- 这是把 M4 的"估算"变成"实证"的关键模块。
- 你把职位分组（本行平级 / 高一档 / 换行目标 / 其它），系统追踪各组的已读率、已读不回率、回复率、邀约率。
- 输出：**竞争力实证报告**——"你在X档抢手、在Y档差某技能、Z方向暂时没戏"，直接指导学习和定位。

### M6. 简历优化与半自动投递（对应需求6）
- **M6.1 匹配打分**：每个职位对你简历打匹配分（技能覆盖、经验匹配、薪资落点）。采用 career-ops 的 Block A-G 七维评估框架（见 `skills/job-eval/`），含 **Block G 岗位真实性鉴别**（幽灵职位/假岗识别：发布新鲜度、描述红旗、公司裁员信号、历史重复发布）。
- **M6.2 简历定制生成**：你维护一份**母版简历**（所有真实项目经验/工作经历/量化成果，越全越好），系统针对每个目标JD从母版中**挑选、重组、改写措辞**——突出最相关经历、补JD高频关键词、把成果改成量化表达，生成该岗位专属简历版本。红线：只重组和润色真实经历，**不伪造**。
- **M6.3 半自动投递**：读取你在表格中标"感兴趣"的岗位，逐个（或分批）投递，**每次投递前展示预览，你确认**；带节流与单日额度保护。

### M7. 招呼语生成（对应需求6）
- 针对每个岗位JD，生成**定制开场招呼语**：点出你与该JD最匹配的1~2个亮点 + 一个针对性问题，控制长度和话术，避免模板感。
- 支持 A/B 话术，用于对照实验，找出你回复率最高的表达方式。

### M8. HR回复与面试邀约管理（对应需求7、需求9的收集部分）
- **M8.1 消息回读**：定时/手动回读平台消息，识别 HR 回复、已读未回、面试邀约。
- **M8.2 回复起草（需求7）**：根据 HR 消息意图（约面/问情况/要简历/谈薪）生成回复草稿，你确认后发送。
- **M8.3 邀约收集与提醒（需求7、9）**：把所有面试邀约汇总成清单（公司、岗位、时间、地点/链接、联系人），标记重要邀约并提醒。

### M9. 面试方向与指导（对应需求9）
- 针对某个邀约，结合该岗位JD + M3市场信息，输出：**可能考察的方向、常见问题、你该准备的重点、你的优势/短板话术、反问HR的问题**。
- 生成一页"面试准备卡"。
- **借鉴 career-ops 强化**（见 `skills/`）：面试前先跑**公司深度研究**（`company-research`，六维分析+本土信息源）；准备包按面试官类型分轨（`interview-prep`，HR/业务负责人/技术同行/群面）；建立跨公司复用的 **STAR+R 故事库**；面试后用 `interview-redflag` 复盘公司红旗信号（四类信号累积计分预警）。

### M10. 决策支持（对应需求8）
- 汇总以上所有数据，回答你最关心的问题：**"该不该跳？能不能换行？我现在值多少钱？下一步学什么？"**
- 输出：一份《个人求职决策报告》，含市场定位、方向建议、技能树、行动清单。
- **新增：Offer 审阅与谈判准备**（借鉴 career-ops，见 `skills/offer-prep/`，补齐原 PRD "拿到 offer 之后"的缺口）：合同条款走查（试用期/五险一金/年终奖/竞业限制重点核对）、口头承诺一致性核对、律师清单与雇主沟通清单分流、回复起草。原则：只准备不代决、合同内容不联网、不凭记忆讲法律。

## 4. 技术架构

```
┌────────────────────────────────────────────────────────┐
│  操作界面层：Excel / 飞书表格（筛选、打"感兴趣"标记）      │
│              + 命令行 CLI（跑各阶段任务）                  │
└────────────────────────────────────────────────────────┘
                          ▲
                          │ 导出/回读
                          ▼
┌────────────────────────────────────────────────────────┐
│  Python 引擎（本地）                                      │
│  ├─ 采集: Playwright(带登录态) + 八爪鱼导入               │
│  ├─ 清洗整合: pandas                                      │
│  ├─ 分析: 市场画像/技能树/竞争力/上下限                    │
│  ├─ 生成: LLM(招呼语/简历建议/HR回复/面试卡)             │
│  └─ 追踪: 消息回读 + 已读不回统计                         │
└────────────────────────────────────────────────────────┘
                          ▲
                          ▼
┌────────────────────────────────────────────────────────┐
│  本地存储: SQLite(结构化) + data/(raw/clean/exports)     │
└────────────────────────────────────────────────────────┘
```

- **语言/栈**：Python 3.11+，Playwright（浏览器自动化），pandas（数据），SQLite（存储），openpyxl（Excel导出）。
- **LLM**：DeepSeek API（OpenAI 兼容接口）。`deepseek-reasoner` 做深度分析（市场画像/竞争力/决策报告），`deepseek-chat` 做高频文案（招呼语/简历改写/HR回复）。API Key 放本地 `config/config.toml`，不入库。
- **登录态**：Playwright 复用你手动登录一次后保存的浏览器会话（`storage_state`），不存明文密码。
- **隐私**：全部本地，简历和数据不上传第三方（除必要的 LLM 调用；可配置脱敏）。

## 5. 数据模型（核心表）

- `jobs`：职位（id, 平台, 岗位名, 公司, 城市, 薪资下限/上限, 经验, 学历, JD原文, 技能标签[], HR活跃度, 采集时间, 分组标签, 匹配分, 感兴趣标记, 投递状态）
- `applications`：投递记录（job_id, 投递时间, 招呼语版本, 状态[已投/已读/已读未回/已回复/已邀约/已拒], 分组）
- `messages`：HR消息（job_id, 方向[收/发], 内容, 意图标签, 时间）
- `interviews`：面试邀约（job_id, 公司, 岗位, 时间, 地点/链接, 联系人, 重要度, 准备卡）
- `skills_market`：市场技能频次（方向, 技能, 出现频次, 关联薪资分位）
- `me`：你的画像（简历技能[], 经验, 期望, 已验证的市场定位）

## 6. 分阶段路线图

我建议**先跑通"探索 + 分析"，验证价值后再上"投递 + 追踪"**，因为后者需要你的账号和真实投递，风险更高、更该在有分析支撑后再做。

| 阶段 | 目标 | 交付物 | 依赖你提供 |
|---|---|---|---|
| **P0 骨架**（本次） | 项目结构、需求文档、配置模板、CLI雏形 | 本文档 + 项目骨架 | — |
| **P1 探索+分析** | 采集行业数据→清洗→市场画像→方向候选→技能树 | 《行业方向 + 技能树》报告 | 你的简历、意向关键词/城市 |
| **P2 半自动投递** | 匹配打分、招呼语生成、表格打标、半自动投递（你确认） | 可投递 + 招呼语库 | 平台登录（你手动登录一次） |
| **P3 追踪+决策** | 已读不回统计、分组对照、HR回复起草、邀约管理、面试卡、决策报告 | 《竞争力实证 + 决策》报告 | 持续运行 1~2 周 |

## 7. 合规与风险清单

| 风险 | 应对 |
|---|---|
| 账号被限流/封禁 | 单账号、节流、单日额度、模拟人工节奏、你确认后发送 |
| 法律（数据/个保/刑法285） | 只抓公开岗位信息、不破解反爬、不采集个人隐私、控制频率 |
| 平台TOS | 个人规模使用、不商用、不转售数据 |
| 简历失真 | 只做"突出重点/补关键词"建议，不伪造经历 |
| HR体验差 | 半自动、每条定制、禁止纯模板轰炸 |
| LLM数据外泄 | 可配置脱敏、Key本地存储、敏感字段不外发 |
