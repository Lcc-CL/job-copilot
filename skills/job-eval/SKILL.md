# 职位评估（Block A-G）

> 改编自 career-ops `modes/zh/oferta.md`（MIT）。对应 job-copilot 模块 M6.1。
> **先读 `skills/shared/求职共享上下文.md`**（评分系统、公司类型分类、中国市场特性、全局规则）。

## 流程

0. 解析 JD → 识别角色画像（见共享上下文画像表）
1. **Block A 岗位速览**：画像、领域、职能、层级、办公模式（远程/混合/坐班）、团队规模、一句话 TL;DR
2. 读母版简历 → **Block B 简历匹配**：JD 要求 → 简历原文逐条映射表（引用简历具体条目佐证）；缺口识别并区分"硬伤 vs 加分项"；每个缺口给缓解策略
3. **Block C 层级与策略**：岗位实际层级 vs 候选人自然层级；如何包装资历的话术；若给的层级偏低的应对预案
4. **Block D 薪酬与需求**：WebSearch 查市场薪资区间（多源）；公司类型分类 → 薪资可信度评级；固定 base vs 浮动拆解（按中国市场特性表：五险一金/年终奖/试用期）；给出 3-6 个向 HR 核实的问题
5. **Block E 简历定制清单**：Top 5 修改项，格式：模块 → 现状 → 建议改法 → 理由（只重组真实经历，不伪造）
6. **Block F 面试准备**：6-10 个 STAR+R 故事映射到 JD 痛点；核心项目演示建议；防守型问题应答
7. **Block G 岗位真实性评估**（独立定性评级，不计入综合分）：
   - **新鲜度**：平台状态（"今日活跃" vs 长期挂着）；发布天数与刷新频率；挂 3 个月以上且频繁重置 = 疑似幽灵职位
   - **描述质量红旗**：职责空泛（不提具体产品/业务线）；要求自相矛盾（如"精通LangChain"+"10年LLM经验"）；薪资区间异常大（如15k-45k，实际offer大概率贴下限或为占位）
   - **公司外部信号**：搜"[公司] 裁员 2026"、"[公司] 劳动仲裁"；融资状态与经营危机报道；发布部门是否刚被裁
   - **历史去重**：与追踪记录里近 90 天的岗位交叉比对，识别同岗换链接的重复发布
   - 评级：**高置信度** / **谨慎推进** / **疑似虚假或已过期**
8. 抽取 15-20 个 ATS 关键词
9. 保存报告到 `reports/{序号}-{公司slug}-{YYYY-MM-DD}.md`，头部含：日期｜URL｜画像｜综合分(/5)｜真实性评级
10. 登记到追踪表（applications，状态="已评估"）

## Boss直聘 场景补充

- 真实性评估额外看：HR 活跃度标签（"刚刚活跃" vs "本月活跃"）、公司认证状态、同公司在招岗位数是否异常
- 综合分 ≥4.0 的岗位标记为"感兴趣"候选，进入招呼语生成（greet）流程
